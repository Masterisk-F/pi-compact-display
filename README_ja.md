# pi-compact-display

Piアシスタント向けの拡張機能です。アシスタントが各種ツール（bash、read、ls、edit など）を実行した際のターミナル（TUI）上での出力表示を、ツールごとに細かくカスタマイズできます。

長すぎるツール出力を制限したり、不要なツール呼び出しを非表示にしてサマリーだけを出力するなど、コンテキストや画面をスッキリと保つのに役立ちます。

![screenshot](https://raw.githubusercontent.com/Masterisk-F/pi-compact-display/master/screenshot1.png)

## 特徴

- **ツールごとの個別設定**: ツールごとに異なる表示モードを設定可能。
- **サマリー表示**: 実行時は非表示にし、結果だけを「⚡ read(1) ls(2)」のようにまとめて表示。
- **行数制限と空行の省略**: 出力行数を制限したり、上下の不要な空行を自動で削除。
- **ツール結果のグループ化**: `grouping` を有効にすると、1ユーザーターン内の `lines` モード呼び出しが1つの集約行（例: `⚡ bash ×3`）にまとまります。
- **Thinkingインジケーターの非表示**: `hideThinking` を有効にすると、思考対応モデルが表示する「Thinking...」インジケーター（および思考ブロック全体）を非表示にできます。
- **外部拡張ツールへの対応**: Pi標準のツールだけでなく、他の拡張機能が追加したツール名も指定して表示を上書き可能。
- **展開への対応**: TUI上で `Ctrl+O` などを押して詳細表示（expanded）を切り替えた際は、制限を解除して全文出力を行います。

## インストールとビルド

### 互換性

**Pi 1.0.1 以降**が必要です。公開 API `pi.registerToolRenderer()` は [Pi 1.0.1（2026-10-03）](https://github.com/earendil-works/pi/releases/tag/v1.0.1) の [commit 1144973](https://github.com/earendil-works/pi/commit/11449730c8a733953ce1bcce70e066bccaa778a5) で追加されました。旧バージョンではアップグレード案内を表示し、ツールの再登録へフォールバックしません。

本拡張は renderer のみを登録し、ツールの execute を置き換えません。`pi-code-intel` が `bash` を登録していても折りたたみを利用でき、RTK、スキーマ、プロンプト、引数準備、実行ロジックを維持します。`mode: "default"` は `next()` で既存 renderer に委譲します。グループ化は TUI 行の追跡を利用するため、Pi 更新時は UI ライフサイクルの互換性も確認してください。

### npmからインストール (推奨)

npm経由で直接インストールすることができます：

```bash
pi install npm:pi-compact-display
```

### ソースからインストール (ローカル開発用)

```bash
# リポジトリへ移動
cd pi-compact-display

# 依存関係のインストール
npm install

# TypeScriptのビルド
npm run build

# Piコマンドを使用して拡張機能をローカルインストール
pi install .
```

## ターン全体の過程を折りたたむ

設定に `"turnFolding": true` を追加し、Pi を再起動または `/reload` してください（既定は無効）。TUI ではユーザー入力ごとに1枚の過程カードを表示し、実行中は最新の進捗とツール回数だけを表示します。途中の説明とツール詳細は折りたたみ、最終回答は全文を残します。失敗・キャンセルは明示し、画像結果は表示を維持します。

`Ctrl+Alt+O` は実行中を含む展開済みカードをすべて折りたたむ専用キーです。繰り返して押しても展開しません。実行中でも完了後でも、fullscreen モードでその過程の見出しをクリックすると個別に展開し、もう一度クリックすると閉じます。一括展開はなく、Pi の `Ctrl+O` も過程カードを開きません（他のツール行には従来どおり作用します）。実行中は既定で折りたたみと最新進捗を表示しますが、手動で展開したカードは新しい進捗やツール結果が届いても開いたままです。実行終了時に過程を自動的に折りたたんで最終回答を全文表示します。過程を展開してもツール個別設定を維持します。`count_only` は非表示、`lines` は行数制限とグループ化、`default` は元の renderer を使用します。過程の開閉や完了でツールの独立した展開状態を変えません。ツール詳細はそのツールの展開操作または `Ctrl+O` で別途確認してください。regular モードでは端末がマウス操作を管理するため、個別展開には fullscreen を使用してください。履歴やモデルへの入力は変更せず、要約のためのモデル呼び出しも行いません。保存済み会話の再表示にも対応します。

有効化には **Pi >=1.1.0** が必要です（`agent_settled.aborted` は 2026-10-07 の Pi 1.1.0 で追加）。古いホストでは UI 変更前に更新／無効化案内を表示します。無効時は Pi >=1.0.1 の従来のツール表示を維持します。**Pi 1.2.0** で検証済みです。公開されたターン renderer API はないため、既存の Container 追跡と行インスタンスの描画ラッパーを利用します。Pi 更新時は互換性を再確認してください。

## 設定ファイルの書き方

設定ファイルは以下の場所に `config.json` という名前で作成します。

**ファイルパス:**
`~/.pi/agent/extensions/pi-compact-display/config.json`

### 設定ファイルの構造

設定はJSON形式で、キーに「ツール名」、値にそのツールの「表示設定（オプション）」を記述します。

```json
{
  "ツール名": {
    "mode": "表示モード",
    "outputLines": 行数,
    "noPadding": true または false
  }
}
```

### 設定できる項目

| プロパティ名 | 型 | 説明 |
| --- | --- | --- |
| **`mode`** | `string` | ツールの表示形式。`"count_only"`, `"lines"`, `"default"` のいずれかを指定します。（必須） |
| **`outputLines`** | `number` | 表示する最大行数。`mode` が `"lines"` のときのみ有効です。（任意） |
| **`noPadding`** | `boolean` | 出力の前後に含まれる空行や、連続する空行を削除するかどうか。`true` で空行を省略します。`mode` が `"lines"` のときのみ有効です。グループ化されている場合、グループカード全体のパディングはリーダー（先頭のツール）の `noPadding` 設定に従います。（任意） |
| **`grouping`** | `boolean` | グローバル設定で `grouping` が有効な場合、このツールをグループカードに含めるかどうか。`false` に設定するとグループ化から除外され、単独のカードとして表示されます。デフォルトは `true` です。（任意） |

### `mode` の種類と挙動

1. **`"count_only"`**
   - **挙動**: ツールが実行されたことや、その出力内容は画面上に一切表示されません。代わりにアシスタントのメッセージの先頭に `⚡ read(1)` のように「実行された回数」がサマリーとしてまとめて表示されます。
   - **用途**: `read`, `ls`, `find`, `grep` など、LLMが自律的に情報を収集するためのツールで、人間がいちいち中身を見る必要がないものに最適です。

2. **`"lines"`**
   - **挙動**: ツールの実行コマンドと、その結果の一部を表示します。`outputLines` で指定した行数のみを表示し、長すぎる出力をカットします。
   - **用途**: `bash`, `edit`, `write` など、LLMがどのような操作を行い、どのようなエラーが出たのかを人間が確認したいツールに最適です。

3. **`"default"`**
   - **挙動**: この拡張機能による表示の書き換えを行わず、Piアシスタントのデフォルトの表示ロジック（または他の拡張機能が定義したロジック）をそのまま適用します。
   - **備考**: 設定ファイルに記述がないツールや、`config.json` 自体が存在しない場合は、全てのツールが自動的に `default` 扱いになります。

### 設定例

```json
{
  "grouping": true,
  "hideThinking": true,
  "user": {
    "noPadding": true
  },
  "skill": {
    "noPadding": true
  },
  "read": { "mode": "count_only" },
  "ls": { "mode": "count_only" },
  "find": { "mode": "count_only" },
  "grep": { "mode": "count_only" },
  
  "bash": { 
    "mode": "lines", 
    "outputLines": 3, 
    "noPadding": true 
  },
  "write": { 
    "mode": "lines", 
    "outputLines": 1, 
    "noPadding": true 
  },
  
  "mcp:tavily_tavily_search": { "mode": "count_only" },
  "mcp__tavily:tavily_search": { "mode": "lines", "outputLines": 5 },
  "mcp": { "mode": "lines", "outputLines": 10 },
  "default": { "mode": "count_only" },

  "my_custom_tool": {
    "mode": "count_only"
  }
}
```

*※ `my_custom_tool` のように、Pi標準ツール以外の別の拡張機能で追加されたツール名であっても指定可能です。*

### サブツール・アクションごとの個別設定（MCPツールなど）

`mcp` ツールのような、内部でさらに別のツールやアクションを呼び出す「ゲートウェイ型のツール」については、引数に応じた個別設定が可能です。

設定の優先順位は、**「サブツールの個別設定 ＞ ツール全体の設定 ＞ `default` キーの設定 ＞ システム標準」** のカスケード（段階的フォールバック）となっており、これはMCPに限らずすべてのツールに共通の仕組みです。

**サブツール名の決定方法（すべてのツールに同一の規則）:**
- 引数 `tool` が文字列なら → `<ツール名>:<値>`（例: `{ "tool": "tavily_search" }` で呼び出すと `mcp:tavily_search`）
- 引数 `action` が文字列なら → `<ツール名>:<値>`（例: `mcp:install`）
- **ツール固有の引数名（`server` / `connect` など）は評価しません。** `mcp` にも専用分岐はなく、これらの引数しか持たない呼び出しは一般的な `mcp` キーにフォールバックします。

**サーバー別プロキシ名（名前空間プロキシ）:**
MCP サーバーの公開方法によっては、ツール名そのものが名前空間付きになることがあります。この名前もそのまま設定キーとして使えます。
- `mcp__<サーバー名>`（例: `mcp__tavily`、サーバー名 `playwright-mcp-chrome` なら `mcp__playwright_mcp_chrome`）
- `mcp__<サーバー名>:<ツール名>`（例: `mcp__tavily:tavily_search`）

`count_only` の集計行にはこの名前がそのまま表示されるため、そのまま設定キーにコピーできます。
`lines` モードでは、コール行に `<実効名> { <引数> }`（例: `mcp__tavily:tavily_search { query: "Node.js 22" }`）と表示され、設定キーとして使う実効名と一致します。

*※この優先順位（個別設定 ＞ `default` 設定）は標準ツール（例: `read`、`bash`）に対しても同じように適用されます。*

### ユーザープロンプトのパディング設定

自身が入力したプロンプト表示の上下の空行（縦方向のパディング）を削除したい場合は、特別に `"user"` というキーを設定して制御することができます。この設定は `"default"` などの他の設定に影響を受けず、明示的に定義された場合のみ適用されます。

**設定例:**
```json
{
  "user": {
    "noPadding": true
  }
}
```

- **`noPadding`** (`boolean`): `true` に設定すると、ユーザー入力プロンプトの上下に挿入される空行（余白）を削除して、表示を非常にコンパクトにします。

### スキル呼び出しのパディング設定

`/skill:...` や `<skill>` ブロックでスキルを呼び出した際に表示される `[skill]` ブロックの上下の空行（縦方向のパディング）を削除したい場合は、特別に `"skill"` というキーを設定して制御することができます。この設定は `"user"` と同様に `"default"` などの他の設定に影響を受けず、明示的に定義された場合のみ適用されます。

**設定例:**
```json
{
  "skill": {
    "noPadding": true
  }
}
```

- **`noPadding`** (`boolean`): `true` に設定すると、`[skill]` ブロックの上下に挿入される空行（余白）を削除して、表示を非常にコンパクトにします。

### グローバル設定: ツール結果のグループ化 (`grouping`)

`lines` モードのツールは通常、呼び出しごとに1つのツールカードとして表示されます。これを有効にすると、**1ユーザーターン内の `lines` モード呼び出しが1つのツールカードにまとまり、集約ヘッダーのみが表示**され、画面の縦方向の使用領域を大幅に減らせます。アシスタントが複数の思考パス（複数のアシスタントメッセージ）に分けて作業しても、同じユーザーターン内は1枚のカードにまとまります。

**設定例:**
```json
{
  "grouping": true,
  "bash": { "mode": "lines", "outputLines": 3, "grouping": false },
  "write": { "mode": "lines", "outputLines": 1 }
}
```

- **`grouping`** (`boolean`): `true` に設定すると、1ユーザーターン内の `lines` モード呼び出し（ツール名が違っても）が1枚のカードにまとまります。カードには件数表示 `⚡ bash ×3 edit ×1` のみが表示されます（1回だけでも `⚡ bash ×1` と表示）。この設定は `"default"` などの他の設定に影響を受けず、明示的に定義された場合のみ適用されます。各ツールの設定で `"grouping": false` を指定すると、そのツールをグループ化から除外できます。
- コマンド行と出力はデフォルトでは非表示です。`Ctrl+O`（展開）でグループ内の全呼び出しのコマンド行と全文（行数制限なし）を確認できます。
- ターンが変わる（ユーザーメッセージを挟む）と呼び出しは別カードに分かれます。

### グローバル設定: Thinkingインジケーターの非表示 (`hideThinking`)

思考対応モデルは `thinking` コンテンツブロックを出力し、Pi はそれを「Thinking...」というラベル（思考表示がオンの場合は思考全文）として描画します。この設定を有効にすると、アシスタントメッセージから thinking ブロックが除去され、「Thinking...」インジケーター（および思考内容）が画面上に表示されなくなります。

**設定例:**
```json
{
  "hideThinking": true
}
```

- **`hideThinking`** (`boolean`): `true` に設定すると、アシスタントメッセージ内の「Thinking...」インジケーターと思考内容を全て非表示にします。この設定は `"user"` や `"grouping"` と同様に `"default"` などの他の設定に影響を受けず、明示的に定義された場合のみ適用されます。

## 使い方・ショートカット

設定が完了したら Pi アシスタントを起動してください。

- **件数表示のクリーンナップ**: `count_only` に設定されたツールは、画面上では `⚡ read(1)` のように表示されますが、裏側でLLMに会話履歴（コンテキスト）が送られる際には、このサマリー文字列は自動的に削除されるため、LLMの思考を邪魔しません。
- **全文表示 (Expanded)**: `lines` モードで出力が省略されている場合、Piの標準機能である表示の展開ショートカット（一般的には `Ctrl+O`）を押すことで、省略されていた全文（行数制限なし）を展開して確認することができます。
