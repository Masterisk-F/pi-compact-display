# pi-compact-display

Piアシスタント向けの拡張機能です。アシスタントが各種ツール（bash、read、ls、edit など）を実行した際のターミナル（TUI）上での出力表示を、ツールごとに細かくカスタマイズできます。

ツール結果をモデルの入力から削除することなく、出力行数の制限、定型的な呼び出しの件数表示、ターン全体の過程の折りたたみで画面をコンパクトにできます。最終回答は全文を残します。

> **ソースブランチの機能:** renderer のみを登録する互換性修正は [PR #9](https://github.com/Masterisk-F/pi-compact-display/pull/9)、ターン全体の折りたたみと時系列を維持するグループ化は [PR #10](https://github.com/Masterisk-F/pi-compact-display/pull/10) で提案中です。これらはまだ npm 未リリースです。試すにはこのソースブランチを使ってください。下記の npm コマンドは公開済みパッケージをインストールします。

![screenshot](https://raw.githubusercontent.com/Masterisk-F/pi-compact-display/master/screenshot1.png)

## 特徴

- **ターン全体の過程の折りたたみ（任意）**: ユーザー入力ごとに途中の説明とツール行を1枚の過程カードにまとめます。実行中は最新進捗、完了後は最終回答の全文を表示します。
- **ツールごとの個別設定**: ツールごとに異なる表示モードを設定可能。
- **サマリー表示**: 定型的なツールのテキストを非表示にし、件数にまとめます。ターン折りたたみが無効なら `⚡ read(1) ls(2)` を最終回答の先頭に、有効な TUI なら過程カードに表示します。
- **行数制限と空行の省略**: 出力行数を制限したり、上下の不要な空行を自動で削除。
- **ツール結果のグループ化**: `grouping` を有効にすると、連続する `lines` モード呼び出しが集約行（例: `⚡ bash ×3`）にまとまります。進捗や他の表示内容をまたがないため、表示順を維持します。
- **Thinkingインジケーターの非表示**: `hideThinking` を有効にすると、思考対応モデルが表示する「Thinking...」インジケーター（および思考ブロック全体）を非表示にできます。
- **外部拡張ツールへの対応**: Pi標準のツールだけでなく、他の拡張機能が追加したツール名も指定して表示を上書き可能。
- **展開への対応**: TUI上で `Ctrl+O` などを押して詳細表示（expanded）を切り替えた際は、制限を解除して全文出力を行います。

## インストールとビルド

### 互換性

**Pi 1.0.1 以降**が必要です。公開 API `pi.registerToolRenderer()` は [Pi 1.0.1（2026-10-03）](https://github.com/earendil-works/pi/releases/tag/v1.0.1) の [commit 1144973](https://github.com/earendil-works/pi/commit/11449730c8a733953ce1bcce70e066bccaa778a5) で追加されました。旧バージョンではアップグレード案内を表示し、ツールの再登録へフォールバックしません。

本拡張は renderer のみを登録し、ツールの execute を置き換えません。`pi-code-intel` が `bash` を登録していても折りたたみを利用でき、RTK、スキーマ、プロンプト、引数準備、実行ロジックを維持します。`mode: "default"` は `next()` で既存 renderer に委譲します。グループ化は TUI 行の追跡を利用するため、Pi 更新時は UI ライフサイクルの互換性も確認してください。

### npmからインストール（公開済みバージョン）

npm経由で直接インストールすることができます：

```bash
pi install npm:pi-compact-display
```

### ソースからインストール (ローカル開発用)

```bash
# PR #10 を別のソースチェックアウトで試す
git clone --branch feat/local-turn-folding https://github.com/lozybean/pi-compact-display.git
cd pi-compact-display

# 依存関係のインストール
npm install

# TypeScriptのビルド
npm run build

# Piコマンドを使用して拡張機能をローカルインストール
pi install .
```

拡張機能は**1つだけ**読み込んでください。npm 版とローカルソースを同時に有効にしないでください。ソース変更後は `npm run build` を実行してから Pi を再起動するか `/reload` します。設定だけの変更なら `/reload` で反映できます。読み込まれるのは `src/index.ts` ではなく `dist/index.js` です。

## ターン全体の過程を折りたたむ

`~/.pi/agent/extensions/pi-compact-display/config.json` で `turnFolding` を `true` にし、Pi を再起動するか `/reload` してください。**既定は無効**です。外側の過程カードだけを制御し、`grouping` と `hideThinking` は独立しています。

### クイックスタート設定

定型的な read は件数のみ、連続するツールはグループ化、未指定のツールもコンパクトに表示する例です。画像ツールは元の renderer を維持します。ツール名は利用中の拡張に合わせてください。

```json
{
  "turnFolding": true,
  "grouping": true,
  "read": { "mode": "count_only" },
  "bash": { "mode": "lines", "outputLines": 4, "noPadding": true },
  "agent": { "mode": "lines", "outputLines": 8, "noPadding": true, "grouping": false },
  "codex_generate_image": { "mode": "default" },
  "default": { "mode": "lines", "outputLines": 4, "noPadding": true }
}
```

### 実行中・展開中・完了後

- **実行中:** 途中の説明とツール行は既定で折りたたまれます。カードには進捗・ツール件数と、最新の説明の全文を端末幅で折り返して表示します。モデルが生成した要約ではなく、1 行に切り詰めません。
- **手動展開:** **fullscreen TUI モード**でその過程の見出しをクリックします。新しい進捗やツール結果が届いても閉じません。もう一度クリックすると閉じます。
- **完了後:** エージェントの処理が実際に終了した時点で過程を自動的に閉じ、最終回答をその下に全文表示します。個々のツールやモデル応答の終了だけでは自動折りたたみしません。
- **失敗・キャンセル:** キャンセル、応答エラー、応答の切り詰めを表示し、ツール失敗件数を集計します。展開しても各ツールの設定を維持するため、`count_only` のエラー本文は非表示のままです。
- **画像:** 画像結果のツール行は過程カードで隠さず、グループ化からも除外します。画像表示には Pi の画像設定と端末の対応が必要です。

進捗件数は空でない途中の assistant テキストメッセージ数です。ツール総数は `count_only` を含むツール行すべて、内側のグループ見出しはそのグループに属する呼び出しだけを数えます。

### 外側の過程表示と内側のツール展開は別

過程を開くと、途中の行を**元の会話上の位置**に表示します。ツールを強制展開したり、状態や設定を変えたりしません。

| 内側の設定 | 外側の過程を開いた後 |
| --- | --- |
| `count_only` | 呼び出し・結果のテキストは非表示のまま。 |
| `lines` + グループ化 | 内側を個別展開していなければ、連続する呼び出しは件数見出しのまま。 |
| `lines` + `grouping: false` | 個別カードのプレビューは `outputLines` を維持。ツール自体を展開すると行数制限を解除。 |
| `default` | ツールを提供した拡張の renderer を維持。 |

過程の開閉、完了、無効化でツールの独立した展開状態を変えません。ツール詳細はそのツールの展開操作または **Ctrl+O** で確認します。逆に **Ctrl+O では過程カードを開きません**。過程の一括展開コマンドはありません。

グループ化が有効でも、展開した過程は次の表示順を保ちます。現在の過程見出しは下記の中国語ラベルを使います。字下げは説明用で、実際の余白を示すものではありません。

```text
▼ 执行过程 · 已完成 · 2 条进度 · 3 次工具调用
  現在の実装を確認…
  ⚡ bash ×2
  修正を適用…
  ⚡ edit ×1
最終回答（常に表示）
```

### 無効化と互換性

`turnFolding` を `false` にするか削除し、`/reload` すると過程カードを取り除いて従来のツール表示へ戻します。`grouping` など他の設定は引き続き有効です。保存済み会話の再表示ではカードを再構成し、履歴を削除しません。

ターン折りたたみは **TUI の表示だけ**に作用します。会話メッセージ、ツール実行、モデル入力、HTML/RPC/JSON/print 出力を変更せず、追加のモデル呼び出しもしません。regular モードのマウス操作は端末が管理するため、個別展開には fullscreen を使ってください。

有効化には **Pi >=1.1.0** が必要です（`agent_settled.aborted` は 2026-10-07 の Pi 1.1.0 で追加）。古いホストでは UI 変更前に更新／無効化案内を表示します。無効時のツール表示は Pi >=1.0.1 に対応します。**Pi 1.2.0** で検証済みです。公開されたターン renderer API はないため、既存の Container 追跡と行インスタンスの描画ラッパーを利用します。Pi 更新時は互換性を再確認してください。

## 設定ファイルの書き方

設定ファイルは以下の場所に `config.json` という名前で作成します。

**ファイルパス:**
`~/.pi/agent/extensions/pi-compact-display/config.json`

### 設定ファイルの構造

同じ JSON オブジェクトにグローバルスイッチ（`turnFolding`、`grouping`、`hideThinking`）、余白設定（`user`、`skill`）、ツール個別設定を記述します。ツールキーには標準ツール、拡張ツール、ゲートウェイのサブツール名を指定できます。

```json
{
  "ツール名": {
    "mode": "lines",
    "outputLines": 4,
    "noPadding": true
  }
}
```

### グローバル設定

| キー | 既定値 | 制御対象 |
| --- | --- | --- |
| `turnFolding` | `false` | 外側の過程カード。TUI 専用、Pi >=1.1.0 が必要。 |
| `grouping` | `false` | 内側の連続する `lines` 呼び出しの集約。過程の折りたたみとは独立。 |
| `hideThinking` | `false` | 思考とインジケーターの表示を抑制。モデル入力からは削除しない。 |
| `default` | `{ "mode": "default" }` | 個別指定のないツールの**設定**。グローバルスイッチや `user`/`skill` には適用しない。 |

設定変更後は Pi を再起動するか `/reload` してください。コメントや末尾カンマのない有効な JSON を使ってください。ファイルがない場合や解析に失敗した場合は空の設定として扱います。

### ツール個別設定

| プロパティ名 | 型 | 説明 |
| --- | --- | --- |
| **`mode`** | `string` | ツールの表示形式。`"count_only"`, `"lines"`, `"default"` のいずれかを指定します。（必須） |
| **`outputLines`** | `number` | `"lines"` モードで未展開時に表示する結果テキストの最大行数。省略時は制限なし。グループ化時は最初に件数だけを表示し、ツール詳細を展開すると行数制限を解除します。（任意） |
| **`noPadding`** | `boolean` | 結果テキスト内のすべての空行（途中の空行も含む）を削除するかどうか。`true` で空行を省略します。`mode` が `"lines"` のときのみ有効です。グループ化されている場合、グループカード全体のパディングはリーダー（先頭のツール）の `noPadding` 設定に従います。（任意） |
| **`grouping`** | `boolean` | グローバル設定で `grouping` が有効な場合、このツールをグループカードに含めるかどうか。`false` に設定するとグループ化から除外され、単独のカードとして表示されます。デフォルトは `true` です。（任意） |

### `mode` の種類と挙動

1. **`"count_only"`**
   - **挙動**: 呼び出しのタイトルと結果テキスト（エラー本文を含む）を非表示にします。ターン折りたたみが無効なら `⚡ read(1)` などを最終回答に、有効な TUI なら過程カードに件数を表示します。画像結果は Pi の画像 renderer が扱います。
   - **エラー**: 件数サマリーのエラー表示や過程カードのツール失敗件数に反映しますが、過程の展開や `Ctrl+O` で `count_only` の本文は表示できません。診断内容を確認したいツールには `lines` または `default` を使ってください。
   - **用途**: `read`, `ls`, `find`, `grep` など、LLMが自律的に情報を収集するためのツールで、人間がいちいち中身を見る必要がないものに最適です。

2. **`"lines"`**
   - **挙動**: グループ化が無効、またはツール個別の `grouping: false` なら、呼び出しと最大 `outputLines` 行の結果テキストを表示します。グループ化が有効なら、**内側のツールグループ自体**を展開するまで件数見出しだけを表示し、展開すると結果テキストを全文表示します。
   - **用途**: `bash`, `edit`, `write` など、LLMがどのような操作を行い、どのようなエラーが出たのかを人間が確認したいツールに最適です。

3. **`"default"`**
   - **挙動**: この拡張機能による表示の書き換えを行わず、Piアシスタントのデフォルトの表示ロジック（または他の拡張機能が定義したロジック）をそのまま適用します。
   - **備考**: 未指定のツールは `default` **設定キー**を継承します。そのキーがない場合や設定ファイル自体がない場合に `mode: "default"` を使います。新しく追加した拡張ツールにも同じ規則を適用します。

### 設定例

```json
{
  "turnFolding": false,
  "grouping": true,
  "hideThinking": true,
  "user": {
    "noPadding": true
  },
  "skill": {
    "noPadding": true
  },
  "read": { "mode": "count_only" },
  "ls": { "mode": "count_only" },
  "find": { "mode": "count_only" },
  "grep": { "mode": "count_only" },
  
  "bash": { 
    "mode": "lines", 
    "outputLines": 3, 
    "noPadding": true 
  },
  "write": { 
    "mode": "lines", 
    "outputLines": 1, 
    "noPadding": true 
  },
  
  "mcp:tavily_tavily_search": { "mode": "count_only" },
  "mcp__tavily:tavily_search": { "mode": "lines", "outputLines": 5 },
  "mcp": { "mode": "lines", "outputLines": 10 },
  "default": { "mode": "count_only" },

  "my_custom_tool": {
    "mode": "count_only"
  }
}
```

*※ `my_custom_tool` のように、Pi標準ツール以外の別の拡張機能で追加されたツール名であっても指定可能です。*

### サブツール・アクションごとの個別設定（MCPツールなど）

`mcp` ツールのような、内部でさらに別のツールやアクションを呼び出す「ゲートウェイ型のツール」については、引数に応じた個別設定が可能です。

設定の優先順位は、**「サブツールの個別設定 ＞ ツール全体の設定 ＞ `default` キーの設定 ＞ システム標準」** のカスケード（段階的フォールバック）となっており、これはMCPに限らずすべてのツールに共通の仕組みです。

**サブツール名の決定方法（すべてのツールに同一の規則）:**
- 引数 `tool` が文字列なら → `<ツール名>:<値>`（例: `{ "tool": "tavily_search" }` で呼び出すと `mcp:tavily_search`）
- 引数 `action` が文字列なら → `<ツール名>:<値>`（例: `mcp:install`）
- **ツール固有の引数名（`server` / `connect` など）は評価しません。** `mcp` にも専用分岐はなく、これらの引数しか持たない呼び出しは一般的な `mcp` キーにフォールバックします。

**サーバー別プロキシ名（名前空間プロキシ）:**
MCP サーバーの公開方法によっては、ツール名そのものが名前空間付きになることがあります。この名前もそのまま設定キーとして使えます。
- `mcp__<サーバー名>`（例: `mcp__tavily`、サーバー名 `playwright-mcp-chrome` なら `mcp__playwright_mcp_chrome`）
- `mcp__<サーバー名>:<ツール名>`（例: `mcp__tavily:tavily_search`）

`count_only` の集計行にはこの名前がそのまま表示されるため、そのまま設定キーにコピーできます。
`lines` モードでは、コール行に `<実効名> { <引数> }`（例: `mcp__tavily:tavily_search { query: "Node.js 22" }`）と表示され、設定キーとして使う実効名と一致します。

*※この優先順位（個別設定 ＞ `default` 設定）は標準ツール（例: `read`、`bash`）に対しても同じように適用されます。*

### ユーザープロンプトのパディング設定

自身が入力したプロンプト表示の上下の空行（縦方向のパディング）を削除したい場合は、特別に `"user"` というキーを設定して制御することができます。この設定は `"default"` などの他の設定に影響を受けず、明示的に定義された場合のみ適用されます。

**設定例:**
```json
{
  "user": {
    "noPadding": true
  }
}
```

- **`noPadding`** (`boolean`): `true` に設定すると、ユーザー入力プロンプトの上下に挿入される空行（余白）を削除して、表示を非常にコンパクトにします。

### スキル呼び出しのパディング設定

`/skill:...` や `<skill>` ブロックでスキルを呼び出した際に表示される `[skill]` ブロックの上下の空行（縦方向のパディング）を削除したい場合は、特別に `"skill"` というキーを設定して制御することができます。この設定は `"user"` と同様に `"default"` などの他の設定に影響を受けず、明示的に定義された場合のみ適用されます。

**設定例:**
```json
{
  "skill": {
    "noPadding": true
  }
}
```

- **`noPadding`** (`boolean`): `true` に設定すると、`[skill]` ブロックの上下に挿入される空行（余白）を削除して、表示を非常にコンパクトにします。

### グローバル設定: ツール結果のグループ化 (`grouping`)

`lines` モードのツールは通常、呼び出しごとに1つのカードとして表示されます。有効時は**連続する呼び出しだけ**を集約します。表示される進捗・思考、警告、カスタムメッセージ、画像結果、独立表示のツールでグループを区切り、「進捗 → ツールグループ → 次の進捗 → 次のグループ」の順序を維持します。

**設定例:**
```json
{
  "grouping": true,
  "bash": { "mode": "lines", "outputLines": 3, "grouping": false },
  "write": { "mode": "lines", "outputLines": 1 }
}
```

- **`grouping`** (`boolean`): `true` に設定すると、連続する `lines` モード呼び出し（ツール名が違っても）をグループごとに1枚のカードへまとめます。カードには件数表示 `⚡ bash ×3 edit ×1` のみが表示されます（1回だけでも `⚡ bash ×1` と表示）。この設定は `"default"` などの他の設定に影響を受けず、明示的に定義された場合のみ適用されます。各ツールの設定で `"grouping": false` を指定すると、そのツールをグループ化から除外できます。
- コマンド行と出力はデフォルトでは非表示です。`Ctrl+O`（展開）でグループ内の全呼び出しのコマンド行と全文（行数制限なし）を確認できます。
- ユーザーメッセージや表示される説明・思考をまたいで集約しません。空の assistant 行、余白、`hideThinking: true` で非表示の思考、非表示の `count_only` ツールは通過できます。画像結果は独立表示です。ストリーミング行に表示内容が届くと、その場でグループを分割します。これは会話の呼び出し順に従う表示機能であり、並列ツールの実行順を直列化しません。

### グローバル設定: Thinkingインジケーターの非表示 (`hideThinking`)

思考対応モデルは `thinking` コンテンツブロックを出力し、Pi はそれを「Thinking...」というラベル（思考表示がオンの場合は思考全文）として描画します。この設定を有効にすると、アシスタントメッセージから thinking ブロックが除去され、「Thinking...」インジケーター（および思考内容）が画面上に表示されなくなります。

**設定例:**
```json
{
  "hideThinking": true
}
```

- **`hideThinking`** (`boolean`): `true` に設定すると、アシスタントメッセージ内の「Thinking...」インジケーターと思考内容を全て非表示にします。この設定は `"user"` や `"grouping"` と同様に `"default"` などの他の設定に影響を受けず、明示的に定義された場合のみ適用されます。

## 使い方・ショートカット

| 操作 | 効果 |
| --- | --- |
| fullscreen TUI で過程見出しをクリック | 実行中でも、その過程だけを開閉。`turnFolding: true` が必要。 |
| エディターから **Ctrl+Alt+O** | 実行中を含む開いている過程をすべて閉じる。繰り返しても展開せず、内側のツール状態を変えない。 |
| 標準の **Ctrl+O**／ツール展開操作 | ツール詳細を独立して制御。外側の過程は開かない。 |
| `/reload` | 設定変更を反映。ソース変更時は先にビルド。 |

TUI のターン折りたたみが無効なら `⚡ read(1)` などの件数サマリーをモデル入力から除去します。有効なら件数は過程カードだけで描画し、最終回答に追加しません。どちらでも生のツール結果はモデルが利用できます。

## トラブルシューティング

- **過程カードがない:** このソースブランチのインストールとビルド、`turnFolding: true`、Pi >=1.1.0、TUI セッションを確認してください。途中の説明やツールがないターンにはカードが出ない場合があります。設定変更後は再読み込みしてください。
- **クリックで開かない:** fullscreen TUI が必要です。regular モードのマウス選択では開閉しません。`Ctrl+O` はツール詳細だけを制御します。
- **過程を開いても4行プレビューがない:** グループ化された `lines` 呼び出しは内側を展開するまで件数だけです。未展開時にも結果プレビューを見たいツールは `grouping: false` にするか、グローバルのグループ化を無効にしてください。
- **未指定のツールが非表示／グループ化される:** `default` 設定キーを確認してください。特定の拡張の renderer を維持するにはそのツールに `{ "mode": "default" }` を明示します。
- **起動時にツールの競合が出る:** npm 版とソース版を同時に読み込まないでください。このブランチの renderer-only 実装は既存の `bash` 実行処理や RTK を置き換えません。
